# Yoga Nature（体式 × 自然）

把用户上传的真实瑜伽照片，与形态、受力和状态相呼应的自然摄影组合成黑白 50:50 二联图。

人物始终使用原片，不抠图、不重绘；AI 只生成自然画面。本 Skill 不绑定 Gemini、OpenAI 或其他固定供应商，而是使用宿主 AI 已经提供并获得用户授权的图片生成能力。

## 运行条件

- 支持读取 `SKILL.md` 的 Codex 或其他 AI Agent。
- 完整成图需要宿主具备图片生成能力；没有时仍可完成姿态分析、候选筛选并输出自然图提示词。
- 本地合成需要 Python 3.10–3.14。
- 本地合成需要 Pillow 10.x–12.x，声明见 `requirements.txt`。

## 安装到 Codex

把本目录复制并命名为 `yoga-nature`，确保入口位于：

```text
%USERPROFILE%\.codex\skills\yoga-nature\SKILL.md   # Windows
~/.codex/skills/yoga-nature/SKILL.md                 # macOS / Linux
```

至少保留以下内容：

```text
yoga-nature/
├── SKILL.md
├── agents/openai.yaml
├── references/
│   ├── pose-lock.md
│   ├── nature-lookup.md
│   ├── style-spec.md
│   └── visual-library.md
├── scripts/
│   ├── preflight.py
│   ├── render_shape_guide.py
│   ├── render_reference_style.py
│   └── render_side_by_side.py
├── requirements.txt
└── assets/                  # 可选视觉参考；外发前确认使用权
```

重新打开 Codex 或开始一个新任务后，用 `$yoga-nature` 显式调用即可。不要把 `examples/`、`tmp/`、`__pycache__/` 或旧测试输出当作安装所需文件。

如果测试环境允许从本地路径加载 Skill，也可以直接让 AI 完整读取本目录的 `SKILL.md`，并将其中相对路径解析到本目录。不要只复制 `SKILL.md` 而遗漏 `references/` 和合成脚本。

## 给其他 AI Agent 使用

如果目标 Agent 支持 Skill、Rules 或 Instructions 目录，把上述最小目录复制到它规定的位置。

如果目标 Agent 没有原生 Skill 机制：

1. 让它完整读取 `SKILL.md`。
2. 让它按 `SKILL.md` 的路由读取相关 `references/*.md`。
3. 明确人物原片不能交给生图模型重绘；生图模型只生成自然画面。
4. 允许它使用自身已有的生图能力；不要要求安装本项目未声明的第三方 API。
5. 若没有生图能力，让它停在“最终自然图提示词”，不得假装已生成图片。

不同生图模型的结果不会完全一致。模型选择、费用、账号和内容政策由测试者使用的宿主平台决定；本项目只规定选择逻辑、提示词边界、验收方法和本地合成方式。

## 使用方式

上传一张有权使用的瑜伽照片，然后发送：

```text
使用 $yoga-nature 处理这张照片。保留人物原片，分析形—势—意，
生成自然摄影并合成为黑白 50:50 二联图。
```

只测试分析与提示词时可以发送：

```text
使用 $yoga-nature 分析这张照片，只给出形态签名、状态句、候选排序和最终自然图提示词，不生成图片。
```

正常流程会：

1. 预检原片。
2. 判断人物第一眼的主表达方式。
3. 把姿态信息分成主关系、次级观察和忽略项，并建立平行的 `form / force / meaning` 三通道签名。
4. 决定左右或上下布局。
5. 跨至少三个自然家族搜索 6–8 个候选。
6. 在生图前淘汰需要摆拍、精确巧合、容易拟人化或缺少现场因果证据的候选。
7. 只给排名前两位写候选卡和短提示词；瞬时介质不写目标几何，只描述自然成因、过程、余波和拍摄条件。
8. 每个候选从零独立生成，不把人物原片交给生图模型，也不连续编辑失败图去贴人体。
9. 遮住人物做第一次盲检，在正常尺寸检查现场因果与摄影连续性，再以 64px 检查整体是否真实、原生、非拟人。
10. 只对自然性通过的图片检查含蓄呼应；某条通道失败就换候选或通道，形与势都弱时使用可观察的哲学意象完成交付。
11. 本地合成为严格 50:50 的黑白二联图并完成最终验收。

## 输出规格

- 纵向长轴动作：4:3 横版，默认 `1440×1080`；人物在左，自然在右。
- 横向、拱形、收拢动作：3:4 竖版，默认 `1080×1440`；自然在上，人物在下。
- 不添加边框、文字、水印、Logo、模糊补边或镜像扩景。
- 中间文件和成品写入当前任务工作区的 `yoga-nature-work/`，不会覆盖原片。

## 依赖预检

Skill 会先只读检查环境：

```bash
python scripts/preflight.py --input "<照片路径>" --workdir yoga-nature-work
```

只有输出中的 `PREFLIGHT_JSON.status` 为 `ok` 才继续。Pillow 缺失时，AI 必须先说明安装范围并获得用户同意，之后才可运行：

```bash
python -m pip install --user -r requirements.txt
```

## 测试建议

建议使用不同形态的照片覆盖：纵向伸展、单腿平衡、横向支撑、后弯、深度折叠和多人动作。每轮检查：

- 人物是否仍是原片，且裁切后保持聚焦和呼吸感。
- 布局是否符合 4:3 / 3:4 规则并严格各占一半。
- 自然对象单独观看是否真实，是否被强迫成标本、几何图标或人体替身。
- 海浪、瀑布、云雾等瞬时介质的形态是否来自生成后筛选，而非提示词直接塑造成目标弧线、竖线或负空间。
- 是否能从画面看到或推断 `成因 → 过程 → 余波`，并找到至少三项相互支持的现场证据。
- 正常尺寸下快门、景深、雾气、锐度和运动是否自洽；是否出现均匀微细节、发光丝带、重复纹理或海报式孤立主体。
- 是否能迅速给自然主体标出头、手臂、躯干、腿等三个以上人体角色；若能则失败。
- 缩到 64px 后是否先读成真实自然，再隐约感到共享的宏观形态、动势或处境；不得要求描出相同人体骨架。
- 回转、开口、凝视或运动方向是否一致。
- 如果只存在左右手性相反，是否仅翻转自然图而没有镜像扩景或扭曲自然物。
- 两者是否共享受力或状态，而不是仅靠说明文字产生意义。
- 黑白后是否保留环境尺度、暗部细节与主体背景分离。

## 参考图片与权利

`assets/` 是可选的风格校准资料，不是生成能力，也不是运行必需项。公开分享或重新打包前，应逐一确认图片为自有、已获授权或许可允许再分发；权利不明的图片应移除。即使保留参考图，也默认只供 Agent 本地观察，不发送给外部生图服务。

用户应拥有输入照片的使用权。宿主是否会把附件上传到其服务端，取决于测试所使用的平台；测试者应自行检查该平台的数据政策。
